# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`ccmud` is a Tamagotchi-style **ambient text MUD** rendered in the Claude Code status line. It plays as a side-effect of using Claude Code: every prompt the user submits silently advances story. The launch genre is `dating-sim` (戀愛養成); the genre is **pluggable via JSON drop-ins** in `genres/`.

The repo is pure bash + jq. There is no build system and no test runner — changes are validated by running `mud.sh` subcommands directly.

Story content is generated by forking `claude -p --model claude-haiku-4-5-20251001` from the `Stop` hook in the **background** (with `disown`), writing the result to a per-session cache file, and **draining that cache on the next Stop hook**. Render never blocks on Haiku.

## Common commands

```bash
bash install.sh                                       # idempotent install to ~/.claude/mud/ + wires settings.json
~/.claude/mud/mud.sh update                           # pull latest mud.sh from GitHub; state.json + settings.json untouched
~/.claude/mud/mud.sh stats                            # JSON dump of current state (after applying decay)
~/.claude/mud/mud.sh hatch <player> [genre]           # reset save (default genre: dating-sim)
~/.claude/mud/mud.sh set-genre <id>                   # swap active genre (state preserved)
~/.claude/mud/mud.sh list-genres                      # list available genre JSON files
~/.claude/mud/mud.sh preview                          # render the LCD once with current state
~/.claude/mud/mud.sh debug-set <field> <value>        # poke any top-level field in state.json
~/.claude/mud/mud.sh usage                            # tail token usage log
echo '{}' | ~/.claude/mud/mud.sh render               # render takes status-line JSON on stdin
```

There is no lint / test runner. After editing `mud.sh`, the fast feedback loops are: `mud.sh stats`, `mud.sh preview`, and `echo '{}' | mud.sh render`.

## Source vs. installed copy

The repo is the *source*; the *runtime* lives at `~/.claude/mud/`. `install.sh` copies `mud.sh` + `genres/*.json` + `prompts/*.txt` there, then merges a `statusLine` + `UserPromptSubmit` + `Stop` hook into `~/.claude/settings.json`. **Editing `mud.sh` in the repo does not affect the running instance** — re-run `install.sh` (or `cp mud.sh ~/.claude/mud/mud.sh`) after changes. `state.json` and `usage.log` are preserved across reinstalls.

`mud.sh update` curls the latest `mud.sh` from GitHub (`richardvt/ccmud@main`; override with `CCMUD_UPDATE_URL`) and replaces the installed script in place. It does *not* touch state, usage log, or settings.

`install.sh`'s settings-merge is matched-by-command and only replaces the ccmud's own entries, so other tools' hooks (e.g. ccpet) on `UserPromptSubmit` / `Stop` are kept.

**Coexistence with ccpet**: only one renderer can hold the `statusLine` at a time. `install.sh` detects an existing statusLine and asks before replacing; UserPromptSubmit and Stop arrays append (both tools' hooks fire).

## Architecture of `mud.sh`

One bash file with three layers:

**State layer.** `state.json` is the single source of truth. Every command that mutates state follows the pattern: `acquire_lock` → `sload` (bulk-read scalars in one `jq` invocation; nested arrays/objects loaded as JSON strings into `MD_*_json` vars) → `apply_decay` → mutate `MD_*` → set `DIRTY=1` → `persist_state` (one `jq -n` call writes everything atomically via temp file + `mv`) → `release_lock`. Locking is `mkdir`-based with a 10-second stale-lock steal — works on both macOS (no `flock`) and Linux. Adding a state field requires updates in three places: `default_state` (initial value), `sload` (jq `[…]` array + matching `MD_*` slot in `read -r`), and `persist_state` (jq `--arg`/`--argjson` + the output object).

**Critical gotcha**: the unit-separator `\x1f` between scalar fields is encoded in the jq source as a literal byte (look at `od -c` to see `037`). If you regenerate `mud.sh` via tooling that strips control characters, `sload` will silently concatenate every field into the first variable. Verify with `sed -n '<sload-line>p' mud.sh | od -c` if `MD_genre` ever contains player names.

**Genre layer.** `load_genre()` reads `~/.claude/mud/genres/$MD_genre.json` and populates `GENRE_*` shell vars (`GENRE_DISPLAY`, `GENRE_PRIMARY_LABEL`, `GENRE_PRIMARY_MAX`, `GENRE_CHAR_EMOJIS_JSON`, `GENRE_SCENE_DECOS_JSON`, `GENRE_FALLBACK_JSON`, `GENRE_SYSTEM_PROMPT`). All genre-driven render and tag logic dispatches via these vars — adding a new genre requires only a JSON file, no code changes.

**Tag DSL.** Haiku output is plain text + `<<TAG…>>` markers. `apply_tag` dispatches over: `AFFECTION±N:char`, `MOOD:mood:char`, `SCENE:name`, `FOCUS:char`, `FLAG±:name`, `ITEM±:name`, `STAT±N:key`, `NEW_CHAR:char`, `ENDING:name`. Each tag mutates the matching `MD_*_json` var via a small `jq` call (acceptable cost — tags only fire on Stop hook drain, not render). Unknown tags log to stderr and are ignored. Malformed `<<…` (no closing `>>`) is preserved as text rather than swallowed.

**Render layer.** `cmd_render` is the hot path — runs every status-line refresh. The frame comes from `render_lcd_frame`: a programmatic 20×8 rounded-corner LCD with the **focus heroine emoji** placed at a random `(row, col)` each call (`$RANDOM`-seeded — every refresh moves her, giving Tamagotchi-style wandering). Scene-driven decoration emojis come from `genre.scene_decos[<scene>]` and pin to top-left + bottom-right. The right side pairs with the LCD rows: header (scene/day/turn) → heroine bars (top 3 by affection) → narrative line → inventory line → quota pin. Stat lines are vertically centered relative to the LCD via `v_offset = (n_sprite - n_stats) / 2`. The bottom `─────` rule width is `$MUD_RULE_WIDTH` (default 80).

**Visual width gotcha.** `vis_width` (used to right-pad sprite rows) counts each codepoint as 1 cell unless it's in `WIDE_RUNTIME` (assembled from `WIDE_EMOJIS_BASE` + the active genre's `char_emojis` values). New emojis added to a genre JSON automatically extend `WIDE_RUNTIME` at runtime. ZWJ sequences and multi-codepoint emoji families are not handled.

## Hook contract

Two hooks injected by `install.sh`:

- **`feed-prompt`** (UserPromptSubmit, 3s timeout): increments `MD_turn`, stamps `last_interaction`, records the user's prompt body to `$TMPDIR/ccmud/<sid>.last_prompt` for the next Haiku call. Cheap, no network.
- **`feed-stop`** (Stop, 15s timeout): parses stdin for `transcript_path` + `rate_limits` + `session_id`. Does three things, in order:
  1. **Drain previous turn's narrative cache** (`$TMPDIR/ccmud/<sid>.next.txt`) — extracts tags via `grep -oE '<<[^>]+>>'`, applies them via `apply_tag`, sets `MD_last_narrative` to the cleaned text. Skips if cache mtime ≤ `MD_last_haiku_at` (already drained).
  2. **Append a row to `usage.log`** — the day's accumulated turn / token counters.
  3. **Fork background `claude -p`** — builds a Haiku context (genre system prompt + state summary + user's last prompt + activity bucket) and pipes it to `claude -p --model claude-haiku-4-5-20251001 --append-system-prompt …`, redirected to a `.tmp` file then atomically `mv`'d to `<sid>.next.txt`. Wrapped in `timeout 60s` so a hung Haiku call doesn't strand. The fork is `&` + `disown`'d so the Stop hook returns instantly.

There is **no API call** for quota: render and feed-stop both parse `rate_limits` directly from Claude Code's stdin JSON envelope (Pro/Max only, after first API response). When stdin is missing or empty, the quota line is hidden.

## Fallback narrative pool

`genres/<id>.json:fallback_snippets` is a list of 50–100 hand-written generic snippets. `maybe_fallback_narrative` (called from `cmd_render` when `MD_narrative_source != "haiku"`) picks one at random and assigns it to `MD_last_narrative` with `narrative_source = "fallback"`. **Fallback snippets do not advance flags, affections, or scene** — they are visual padding only, used when:

- First install (no Haiku call has fired yet)
- Haiku is mid-flight or just failed (cache empty)
- `claude` CLI not on PATH

Render dims fallback narratives (`\033[2;36m` vs `\033[36m` for Haiku output) so the user can tell at a glance.

## Conventions

- All state mutations go through `acquire_lock` / `sload` / `persist_state` — don't read or write `state.json` directly except in `cmd_hatch` (which intentionally clobbers everything) and `cmd_debug_set`.
- `DIRTY=0` short-circuits `persist_state`; only set `DIRTY=1` when an `MD_*` var actually changed.
- Nested objects/arrays (`affections`, `moods`, `flags`, `inventory`, `stats`, `active_chars`) live as JSON strings in `MD_*_json` vars and are mutated via `jq -c …` — one extra `jq` call per tag is fine; tags fire only on Stop hook drain.
- Heredoc-quote inline awk/jq programs (`'…'`) — bash variables inside them won't expand.
- Hooks have hard timeouts in `settings.json` (3s prompt, 15s stop). Don't add synchronous network calls. Background `claude -p` is `&` + `disown` and runs entirely outside the hook timeout window.
- Adding a new genre = a single JSON file in `genres/` (see `genres/README.md`). No code changes required unless you introduce a new tag type.
- When adding a new tag type, update three places: `apply_tag` (dispatcher), `genre.tag_schema` (Haiku-facing format), `genre.system_prompt` (Haiku rules). And document it in `CLAUDE.md`.

## Privacy / data flow

The user's Claude Code prompt body is forwarded (truncated to 800 chars) to the background `claude -p` call so Haiku can produce contextually-relevant narrative. This is the explicit design; if a user wants to disable, they can either:
- Delete `$TMPDIR/ccmud/<sid>.last_prompt` from the UserPromptSubmit hook
- Comment out the prompt-write line in `cmd_feed_prompt`

The Stop hook background `claude -p` uses the user's logged-in `claude` CLI session — so each generation counts against the user's quota. The `usage` subcommand logs daily token totals so the cost is visible.
